1. Tổng quan hệ thống

Hệ thống gồm hai khối. Khối nghiệp vụ quản lý nhà hàng với 5 module: Danh mục, Bán hàng, Kho, Báo cáo, Cài đặt. Khối trợ lý AI cho phép hỏi dữ liệu kinh doanh bằng tiếng Việt; câu hỏi được chuyển thành SQL, kiểm duyệt rồi mới chạy.

1.1 Kiến trúc

Trình duyệt ──▶ Next.js (web, cổng 3000) ──HTTP──▶ FastAPI (api, cổng 8000) ──SQL──▶ MySQL 8.4 (Docker, cổng 3306)
                                                         │
                                                         ├──▶ LLM: DeepSeek / OpenAI / Ollama (trợ lý AI)
                                                         └──▶ SePay (thanh toán VietQR, tuỳ chọn)

1.2 Thành phần trong kho mã

Thư mụcNội dung

1.3 Thứ tự tổng quát

Làm đúng thứ tự dưới đây; mỗi bước phụ thuộc bước trước:

  1. Cài công cụ (mục 2) → lấy mã (mục 3) → cài thư viện (mục 4).
  2. Tạo file .env (mục 5) → bật MySQL (mục 6) → tạo bảng (mục 7).
  3. Tạo view + tài khoản chỉ-đọc cho AI (mục 8) → sinh dữ liệu mẫu (mục 9).
  4. Chạy API (mục 10) và web (mục 11) ở hai cửa sổ Terminal riêng → mở trình duyệt.
Thời gian dự kiếnLần đầu khoảng 30–45 phút (chủ yếu là tải Docker image, thư viện và sinh dữ liệu mẫu). Những lần sau chỉ cần 2 lệnh make api và make web.

2. Chuẩn bị máy và cài công cụ

2.1 Cấu hình tối thiểu

  • RAM 8 GB (khuyến nghị 16 GB nếu chạy Ollama cục bộ), trống ≥ 10 GB ổ đĩa.
  • Kết nối Internet cho lần cài đầu (tải thư viện, Docker image) và khi dùng LLM thương mại.

2.3 Cài trên macOS

1

Cài Homebrew (trình quản lý gói) nếu máy chưa có. Mở ứng dụng Terminal và dán:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Cài xong, làm theo 2 dòng "Next steps" mà Homebrew in ra (thêm brew vào PATH), rồi đóng và mở lại Terminal.

2

Cài Git, uv, Node.js:

brew install git uv node
3

Bật pnpm đúng phiên bản bằng Corepack (đi kèm Node.js):

corepack enable
corepack prepare pnpm@9.15.0 --activate
4

Cài Python 3.12 qua uv (không đụng tới Python của hệ điều hành):

uv python install 3.12
5

Cài Docker Desktop (docker.com/products/docker-desktop) hoặc OrbStack (orbstack.dev — nhẹ hơn trên Mac). Mở ứng dụng lên một lần và chờ biểu tượng báo "running".

6

Kiểm tra lại toàn bộ. Mỗi lệnh phải in ra số phiên bản, không báo "command not found":

git --version
uv --version
uv run --python 3.12 python --version   # Python 3.12.x
node --version                          # v20 trở lên
pnpm --version                          # 9.15.0
docker --version
docker compose version
make --version

2.4 Cài trên Windows (qua WSL2)

Makefile và script apply_grants.sh dùng bash, nên trên Windows nên chạy trong WSL2 (Ubuntu):

  1. Mở PowerShell quyền Administrator: wsl --install -d Ubuntu, khởi động lại máy, tạo tài khoản Ubuntu.
  2. Cài Docker Desktop cho Windows, vào Settings → Resources → WSL integration, bật cho Ubuntu.
  3. Trong cửa sổ Ubuntu: sudo apt update && sudo apt install -y git make curl, cài uv bằng curl -LsSf https://astral.sh/uv/install.sh | sh, cài Node 20 bằng nvm hoặc gói NodeSource, rồi làm tiếp bước 3–6 ở mục 2.3.
  4. Để mã nguồn trong ổ Linux (ví dụ ~/projects), không đặt trong /mnt/c — chạy sẽ chậm hơn nhiều.
Không dùng WSL?Vẫn chạy được bằng cách gõ tay các lệnh mà Makefile gọi (xem mục 16), và dùng scripts/apply_grants.ps1 thay cho apply_grants.sh.

Lệnh này làm hai việc:

Thành công khiLệnh kết thúc không có dòng error; thấy thư mục apps/api/.venv và apps/web/node_modules.
Nếu pnpm báo sai phiên bảnChạy lại corepack prepare pnpm@9.15.0 --activate. Nếu uv báo thiếu Python 3.12, chạy uv python install 3.12.

Tuỳ chọn cho người đóng góp mã: cài hook kiểm tra định dạng trước mỗi commit bằng pipx install pre-commit && pre-commit install.

5. Cấu hình biến môi trường

Tạo file .env ở thư mục gốc từ file mẫu .env.example:

make env

Lệnh chỉ tạo .env nếu chưa có, nên chạy lại nhiều lần cũng không sao. Mở .env bằng trình soạn thảo bất kỳ (VS Code: code .env). Với máy phát triển, giữ nguyên giá trị mặc định là chạy được; chỉ cần điền thêm phần AI (mục 8, 13) và SePay (mục 14) khi dùng tới.

Không bao giờ commit file .envFile này chứa mật khẩu và khoá API. Nó đã nằm trong .gitignore; chỉ .env.example (không có giá trị bí mật) mới được đưa lên Git.

6. Khởi động MySQL bằng Docker

1

Mở Docker Desktop / OrbStack và đợi nó chạy. Sau đó:

make db-up

Lần đầu Docker tải image mysql:8.4 (vài trăm MB). Container tên restaurant-db, dữ liệu nằm trong volume db-data nên tắt/bật lại không mất.

2

Chờ MySQL sẵn sàng (khoảng 20–40 giây lần đầu). Kiểm tra:

docker compose ps

Cột STATUS phải là Up … (healthy). Nếu còn (health: starting) thì đợi thêm rồi chạy lại.

3

(Tuỳ chọn) vào thử MySQL bằng dòng lệnh:

docker compose exec db mysql -urestaurant -prestaurant restaurant -e "SELECT VERSION();"

Tắt MySQL: make db-down (dữ liệu vẫn giữ). Múi giờ container đặt sẵn Asia/Ho_Chi_Minh, bảng mã utf8mb4 để lưu tiếng Việt có dấu.

7. Tạo lược đồ CSDL (migration)

make migrate

Alembic chạy toàn bộ migration trong apps/api/migrations/versions, tạo 29 bảng nghiệp vụ theo báo cáo (MON_AN, ORDER, HOA_DON, NGUYEN_LIEU…) cộng bảng đếm DEM_ORDER.

Thành công khiDòng cuối có dạng Running upgrade … -> … và không có Traceback. Kiểm tra: docker compose exec db mysql -urestaurant -prestaurant restaurant -e "SHOW TABLES;".
Nếu báo "Can't connect to MySQL server"MySQL chưa healthy (quay lại mục 6, bước 2) hoặc cổng 3306 đang bị một MySQL khác trên máy chiếm (xem mục 17).

8. View và tài khoản chỉ-đọc cho trợ lý AI

Trợ lý AI không đọc thẳng bảng nghiệp vụ. Mỗi vai trò chỉ thấy một view, và truy vấn bằng một tài khoản MySQL riêng chỉ có quyền SELECT trên đúng view đó (NFR-06):

Vai tròViewTài khoản MySQL
Quản lývw_ai_quanlyai_manager
Thu ngânvw_ai_thunganai_cashier
Thủ khovw_ai_khoai_warehouse
1

Chọn 3 mật khẩu riêng (chỉ dùng chữ và số cho dễ đặt vào URL), đặt vào biến tạm của Terminal:

export AI_READONLY_PASSWORD_MANAGER='DoiMatKhauQuanLy1'
export AI_READONLY_PASSWORD_CASHIER='DoiMatKhauThuNgan1'
export AI_READONLY_PASSWORD_WAREHOUSE='DoiMatKhauKho1'
2

Chạy script. Script đọc 3 file view trong db/views/, tạo view trong CSDL, rồi tạo/đổi mật khẩu và cấp quyền cho 3 tài khoản:

./scripts/apply_grants.sh

Windows PowerShell: đặt $env:AI_READONLY_PASSWORD_MANAGER="…" (tương tự cho 2 biến kia) rồi powershell -ExecutionPolicy Bypass -File scripts/apply_grants.ps1. Nếu đổi MYSQL_ROOT_PASSWORD, export thêm biến đó trước khi chạy.

3

Điền 3 chuỗi kết nối vào .env, đúng mật khẩu vừa đặt:

AI_READONLY_URL_MANAGER=mysql+asyncmy://ai_manager:DoiMatKhauQuanLy1@localhost:3306/restaurant?charset=utf8mb4
AI_READONLY_URL_CASHIER=mysql+asyncmy://ai_cashier:DoiMatKhauThuNgan1@localhost:3306/restaurant?charset=utf8mb4
AI_READONLY_URL_WAREHOUSE=mysql+asyncmy://ai_warehouse:DoiMatKhauKho1@localhost:3306/restaurant?charset=utf8mb4
Mật khẩu có ký tự đặc biệt?Các ký tự @ : / ? # % phải mã hoá URL trong chuỗi kết nối (ví dụ @ thành %40). Dùng chữ và số là cách đơn giản nhất.
Chạy lại sau mỗi lần tạo lại CSDLView và tài khoản nằm trong CSDL. Nếu xoá volume và chạy lại migration (mục 9.4), phải chạy lại apply_grants.sh.

9. Sinh dữ liệu mẫu 12 tháng

CSDL mới tạo chưa có tài khoản nào để đăng nhập. Script seed tạo toàn bộ dữ liệu để dùng thử và làm báo cáo: vai trò, cấu hình, khoảng 70 món, nguyên liệu, công thức, 24 bàn, 3 tài khoản mẫu và khoảng 20.000 order trong 12 tháng (có phiếu nhập, xuất kho, thanh toán, trừ kho FIFO, Business Date 06:00–06:00).

9.1 Chạy seed

make seed

Mất vài phút tuỳ máy. Kết thúc sẽ in dạng:

[seed] danh mục: 71 món · … nguyên liệu · 24 bàn
[seed] vận hành: … order · … phiếu nhập · … phiếu xuất
[seed] xong lúc 2026-…

9.2 Tuỳ chỉnh lượng dữ liệu

Muốn chạy nhanh để thử (ít order hơn):

cd apps/api
uv run python ../../scripts/seed/generate.py --orders 3000 --months 3 --seed 42
cd ../..

--orders: số order (mặc định 20.000) · --months: số tháng lùi về trước (12) · --seed: hạt giống ngẫu nhiên, cùng số thì ra cùng dữ liệu (42).

10. Chạy backend (API)

Mở một cửa sổ Terminal riêng cho API (để nó chạy suốt):

make api

Tương đương cd apps/api && uv run uvicorn app.main:app --reload --app-dir src --port 8000. Chế độ --reload tự khởi động lại khi sửa mã.

Thành công khiTerminal in Application startup complete và Uvicorn running on http://127.0.0.1:8000. Mở http://localhost:8000/docs để xem toàn bộ API (Swagger) và gọi thử từng endpoint.

Dừng API: bấm Ctrl + C trong cửa sổ đó. Sửa .env xong phải dừng rồi chạy lại để API đọc giá trị mới.

12. Dùng thử các chức năng

12.1 Bán hàng — 3 bước (đăng nhập seed_cashier)

  1. Chọn bàn. Lưới bàn hiện trạng thái: Trống (xanh), Có khách (đen, kèm tạm tính, số món, giờ mở), Đã đặt (xám). Lọc theo trạng thái ở thanh phía trên; ô "Tra mã order" để tìm order cũ.
  2. Bấm bàn trống → sang bước Gọi món với order mới. Bấm bàn có khách → khung bên phải hiện tóm tắt với nút Gọi thêm và Thanh toán. Đơn mang về: nút Đơn mới ở khung "Mang về".
  3. Gọi món. Mỗi ô món hiện giá; bấm để thêm, dùng +/− để đổi số lượng, thêm ghi chú cho bếp. Món chưa có giá hiện "Chưa có giá" và không thêm được. Giỏ hàng chia "Món mới" và "Đã gửi bếp", tổng tiền cập nhật ngay.
  4. Bấm Gửi bếp (quay về sơ đồ bàn) hoặc Gửi bếp & thanh toán (sang bước 3).
  5. Thanh toán. Chọn Tiền mặt: nhập tiền khách đưa hoặc bấm nút nhanh ("Vừa đủ", 50.000, 100.000…), màn hình tính tiền thối, bấm Xác nhận đã thu. Hoặc chọn QR chuyển khoản (mục 14).
  6. Màn Hoàn tất hiện số hoá đơn, mã order, phương thức, tổng tiền, tiền thối, nút In hoá đơn và Về sơ đồ bàn. Bàn tự chuyển về Trống.

Vị trí đang làm được lưu trên thanh địa chỉ (/sales?step=pay&order=…), nên tải lại trang không mất chỗ.

12.3 Trợ lý AI

  • Màn đầy đủ (mục "Trợ lý AI"): cột lịch sử trò chuyện bên trái, màn chào với 4 câu hỏi gợi ý theo vai trò. Câu trả lời gồm câu kết luận, các ý chính, tab Biểu đồ / Bảng / SQL, ghi chú phạm vi dữ liệu, nút Sao chép, Hỏi lại và các câu Hỏi tiếp.
  • Ô chat nổi ở góc dưới phải mọi màn (trừ Bán hàng và màn Trợ lý). Mở/đóng bằng Ctrl + K (Mac: ⌘ + K), Esc để thu nhỏ; nút "Mở toàn màn hình" chuyển sang màn đầy đủ đúng phiên đang hỏi.
  • Trợ lý chỉ đọc dữ liệu và chỉ trong phạm vi vai trò. Cần cấu hình LLM (mục 13) và tài khoản chỉ-đọc (mục 8) mới trả lời được.

13. Cấu hình trợ lý AI (LLM)

Chọn một trong ba cách, sửa .env, rồi khởi động lại API.

13.1 DeepSeek (mặc định, rẻ, nhanh)

  1. Tạo tài khoản tại platform.deepseek.com, nạp tiền tối thiểu, vào API Keys → tạo khoá.
  2. Trong .env:
AI_PROVIDER=deepseek
AI_API_KEY=sk-...khoá-của-bạn...
LLM_MODEL=deepseek-flash      # mặc định của dự án

Để trống LLM_BASE_URL (dùng https://api.deepseek.com). LLM_REASONING_EFFORT=low giữ mỗi câu hỏi trong ngân sách 8 giây (NFR-02).

13.2 OpenAI

AI_PROVIDER=openai
AI_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini           # ví dụ; chọn mô hình còn hỗ trợ trong tài khoản của bạn

13.3 Ollama (chạy mô hình ngay trên máy, không cần khoá)

  1. Cài Ollama (ollama.com) và mở ứng dụng.
  2. Tải một mô hình giỏi SQL, ví dụ: ollama pull qwen2.5-coder:7b (khoảng 4–5 GB).
  3. Trong .env:
AI_PROVIDER=ollama
LLM_MODEL=qwen2.5-coder:7b
AI_OLLAMA_BASE_URL=http://localhost:11434
Kiểm tra nhanhĐăng nhập seed_manager → Trợ lý AI → bấm gợi ý "Doanh thu 7 ngày gần nhất theo từng ngày?". Có bảng và biểu đồ là đã thông. Nếu báo lỗi, xem API log trong cửa sổ make api và mục 17.

Các giới hạn an toàn luôn bật: mọi câu SQL do mô hình sinh ra phải qua bộ kiểm duyệt validate_sql (chỉ SELECT trên đúng view), tối đa 500 dòng, 3 giây mỗi truy vấn, 2 lần sinh SQL mỗi câu hỏi, hạn mức AI_DAILY_QUESTION_QUOTA câu/ngày.

14. Thanh toán QR qua SePay

Có hai chế độ, chọn bằng PAYMENT_GATEWAY:

  • simulator (mặc định): cổng giả lập dùng cho kiểm thử tự động. Trên màn thanh toán vẫn tạo được giao dịch QR có đếm ngược 10 phút; khi demo, dùng Tiền mặt hoặc luồng "Khách báo đã chuyển khoản → Chờ đối soát → Quản lý xác nhận".
  • sepay: mã VietQR chuyển khoản thật qua SePay ở Test mode (không mất tiền), hệ thống tự xác nhận khi SePay gọi webhook.

14.1 Chuẩn bị SePay Test mode

1

Đăng ký tài khoản tại my.sepay.vn, bật Test mode (chế độ thử nghiệm) trên thanh bên, tạo một tài khoản ngân hàng Test mode. Ghi lại số tài khoản, mã ngân hàng và tên chủ tài khoản.

2

Trong mục Cấu trúc mã thanh toán, khai báo tiền tố TT (phải trùng SEPAY_PAYMENT_PREFIX). Mỗi giao dịch có nội dung dạng TT388.

3

Mở đường hầm HTTPS để SePay gọi được máy của bạn. Cài cloudflared (brew install cloudflared) rồi chạy trong cửa sổ Terminal thứ ba:

cloudflared tunnel --url http://localhost:8000

Cloudflared in ra một địa chỉ dạng https://ten-ngau-nhien.trycloudflare.com.

4

Trong SePay, thêm webhook: URL https://ten-ngau-nhien.trycloudflare.com/api/v1/sales/webhooks/sepay, kiểu xác thực API Key, đặt một chuỗi khoá ngẫu nhiên (ví dụ openssl rand -hex 24). (Tuỳ chọn) tạo API Token để dùng nút "Kiểm tra lại".

14.2 Cấu hình .env

PAYMENT_GATEWAY=sepay
SEPAY_BANK_ACCOUNT=0123499999          # số tài khoản Test mode
SEPAY_BANK_CODE=MBBank                 # mã ngân hàng theo SePay
SEPAY_ACCOUNT_NAME=NHA HANG DEMO
SEPAY_WEBHOOK_API_KEY=chuoi-khoa-o-buoc-4
SEPAY_API_TOKEN=token-tuy-chon
SEPAY_PAYMENT_PREFIX=TT

Khởi động lại API. Thiếu số tài khoản, mã ngân hàng hoặc API key thì API sẽ báo lỗi ngay khi khởi động — đây là cố ý để không chạy với cấu hình thiếu.

14.3 Demo một giao dịch

  1. Bán hàng → chọn bàn có khách → Thanh toán → QR chuyển khoản → Tạo mã QR. Màn hình hiện mã VietQR, số tiền, ngân hàng, số tài khoản, nội dung chuyển khoản (có nút sao chép) và đếm ngược 10 phút.
  2. Trong trang SePay, dùng Giả lập giao dịch với đúng số tiền và đúng nội dung (ví dụ TT388).
  3. Trong vòng vài giây màn thu ngân tự chuyển sang Hoàn tất. Không có tunnel thì bấm Kiểm tra lại (cần SEPAY_API_TOKEN).

15. Kiểm thử và đánh giá

15.1 Cổng kiểm tra đầy đủ (chạy trước khi commit)

make gate

Chạy lần lượt: kiểm tra định dạng (ruff format, prettier) → lint (ruff, ESLint) → kiểu (mypy, tsc) → test (pytest, vitest) → build web. Mọi bước phải xanh. Bộ test dùng CSDL SQLite trong bộ nhớ và LLM giả, không cần MySQL, khoá API hay mạng.

make fmt            # tự sửa định dạng
make test-api       # chỉ backend:  cd apps/api && uv run pytest
make test-web       # chỉ frontend: cd apps/web && pnpm test
cd apps/api && uv run pytest tests/modules/test_sales_payments.py -q   # một file

15.2 Kiểm thử trên MySQL thật (tuỳ chọn)

make gate-full      # gate + test integration nếu máy đủ RAM/đĩa và MySQL đang chạy

15.3 Đánh giá trợ lý AI (thực nghiệm A/B/C)

Cần MySQL có dữ liệu seed, tài khoản chỉ-đọc và LLM đã cấu hình:

cd apps/api
uv run python ../../data/eval/harness.py --configs A,B,C --out ../../docs/eval-results.json

Chạy 95 câu hỏi trong data/eval/questions.jsonl, ghi kết quả vào docs/eval-results.json. Lần chạy tốn phí LLM thật.

17.1 Khi cần báo lỗi cho nhóm

Gửi kèm: lệnh vừa chạy, 20 dòng cuối trong Terminal, đầu ra của git log --oneline -1 và docker compose ps. Xoá mọi khoá API, mật khẩu khỏi nội dung trước khi gửi.

Tóm tắt lần chạy đầu tiên make setup → make env → make db-up → make migrate → ./scripts/apply_grants.sh (sau khi export 3 mật khẩu, rồi điền AI_READONLY_URL_* vào .env) → make seed → make api (cửa sổ 1) → make web (cửa sổ 2) → mở http://localhost:3000, đăng nhập seed_manager / matkhau123.
